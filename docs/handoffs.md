# Handoffs between tasks (jewelvault-app)

One heading per task; the next task reads the lines of the tasks it depends on. (The API repository keeps the same kind of file.)

## WEB14 Hosting headers (vercel.json), build checks, no source maps, API address only
- `vercel.json` sets on every path: Strict-Transport-Security (2 years, includeSubDomains), nosniff, Referrer-Policy strict-origin-when-cross-origin, X-Frame-Options DENY, a Permissions-Policy that allows only the camera for the site itself (the scanner of scan-detail uses getUserMedia) and a `Content-Security-Policy-Report-Only` (report-only first, H1): `default-src 'self'`, inline scripts and styles allowed (a static export cannot use nonces), `connect-src` and `img-src` name `https://billing-api.jaishrigoldpalace.com` and no other outside origin, `data:` and `blob:` for images (QR codes, barcodes, photos picked on the device). The enforcing header replaces the report-only one after staging's reports are read (a decision of Harsh).
- STAGING: a header file is static, so the staging website project (`billing-staging.`, its API is `billing-api-staging.`) would report every call against the production API origin. Options for the orchestrator and Harsh: a second Vercel project with its own `vercel.json` (Vercel reads `vercel.json` from the project's root directory setting), or name both API origins in the policy (a second outside origin, which T-D12 as written forbids). Nothing is enforced yet, so nothing breaks; `npm run check:build` prints a note when NEXT_PUBLIC_API_URL names an origin that vercel.json does not.
- `npm run build && npm run check:build` (scripts/check-build.mjs; `--out`, `--src`, `--vercel`, `--no-headers`). It fails on: `mysql://`, `mariadb://`, `DB_PASSWORD`, `DATABASE_URL`, `admin123`, `staff123` or any `.map` file in `out/`; a route of `src/app` without its static page (and the 404 page); `dangerouslySetInnerHTML` or `innerHTML` in `src/` (found with the TypeScript parser: comments do not count); a build-time variable other than `NEXT_PUBLIC_API_URL`, or any `process.env.X` that is not `NEXT_PUBLIC_`; and, from `vercel.json`, a missing header, an outside origin other than the API's, the API origin missing from `connect-src` or `img-src`, eval, a wildcard, a bare scheme, or the word Supabase.
- `TOLERATED` in scripts/check-build.mjs lists the names the code still reads: `NEXT_PUBLIC_PREVIEW_MODE` and the two `NEXT_PUBLIC_SUPABASE_*` of the Supabase build. They are printed as notes. WEB15 deletes the Supabase pieces and the preview switch and must empty that list; WEB01 reads `NEXT_PUBLIC_API_URL` (already allowed). `document.write` (src/lib/exportUtils.ts opens a print window) is not on the list of H3, so it is not checked.
- Run on the real build of this commit: `npm run build` and `NEXT_PUBLIC_PREVIEW_MODE=1 npm run build` both give 16 static routes (15 pages and the not-found page), and `npm run check:build` passes on each; planted `admin123` in `out/`, a `.map` file and an `innerHTML` in `src/` each make it fail (shown). `next build` also type-checks `tests/`, so a test that imports a `.mjs` needs JSDoc types on its exports.
